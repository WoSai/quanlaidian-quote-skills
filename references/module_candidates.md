# 对话场景下的模块推荐候选短列表

> 完整 SKU + 价格请见 `product_catalog.md`，本文件仅给出**对话场景下的推荐候选短列表**，用于无原生表单时引导销售/售前快速勾选。

## 门店增值模块候选

> **「无门店增值模块」选项**：飞书卡片 / 引导式对话兜底里都应把 `无门店增值模块` 作为第一个可选项呈现，让"不要增值模块"成为显式表态，而非靠"全部不勾"推断。Agent 收到用户同勾「无门店增值模块」+ 其他模块时，以「无」为准、清空其他勾选（详见 `SKILL.md` 卡片答案 → API 字段修正映射）。OpenClaw 原生表单已在 schema 用 `none_option.exclusive` 声明互斥，点击时即生效；飞书卡片 / 引导式对话路径点击时拦不住，仍走提交后兜底。

## 业态 → 门店增值模块推荐映射

> 当 `references/dining_type_keywords.md` 一级关键词命中、餐饮类型已自动判定时，可顺势按下表对**门店增值模块**做卡片推荐标记。**飞书卡片不支持默认勾选**（`feishu_ask_user_question` 没有 default-checked 参数），所以推荐方式是：① 给推荐项 `label` 加 `⭐推荐 ` 前缀；② 在 `description` 写明推荐理由（如"咖啡业态常配"）；③ 在卡片 `question` 文案里写"已标记 N 项推荐模块（⭐），需要的请勾选"。引导式对话兜底路径可以代销售直接勾上，销售明确取消才撤回。
>
> **绝不**在卡片外文字声称"已为你预选 / 已默认勾上"——卡片渲染没勾就是没勾，措辞要和实际一致，否则用户会以为系统出 bug。
>
> **推荐范围限定**：仅推荐能映射到 `product_catalog.md` 的标准 SKU。"收银 / 桌台管理 / 小程序 / 外卖接单 / 会员营销 / 集团管理"在套餐里已内置，不出现在增值模块推荐里。"码牌收银 / 点菜宝 / 无收银点餐 / 挂账"目前没有对应 SKU（套餐内置功能或硬件），同样不推荐。
>
> **不推荐总部模块**：`配送中心` / `生产加工` 依赖客户是否自建中央厨房/配送中心，由销售按实际情况选；提前标记会破坏『套餐默认决策树』（旗舰版 vs 全能版）的默认行为。

### 推荐冲突与降级

- 同一句品牌名命中多个子业态（如"火锅 + 烧烤店"复合品牌）：取**最先命中**的子业态推荐，其它的不叠加，避免给销售一个臃肿的推荐集。
- 子业态命中但餐饮类型走了『歧义 → 显式追问』路径：此时餐饮类型尚未定，**不要**先标记增值模块；等用户确认餐饮类型后再标记。
- 若客户首条消息已经显式列出了所需模块（例如"我们要 KDS 和宴秘书"），以客户表述为准，业态推荐项只在客户列出的基础上补全，不覆盖客户的明确表态。
