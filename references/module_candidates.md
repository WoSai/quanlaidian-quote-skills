## 业态 → 门店增值模块预填映射

> 当 `references/dining_type_keywords.md` 一级关键词命中、餐饮类型已自动判定时，可顺势按下表对**门店增值模块**做卡片预选（卡片 2 多选项默认勾上）。预选后的勾选项是建议值，**销售可在卡片里取消**，不强制。
>
> **预填范围限定**：仅预填能映射到 `product_catalog.md` 的标准 SKU。"收银 / 桌台管理 / 小程序 / 外卖接单 / 会员营销 / 集团管理"在套餐里已内置，不出现在增值模块预选里。"码牌收银 / 点菜宝 / 无收银点餐 / 挂账"目前没有对应 SKU（套餐内置功能或硬件），同样不预填。
>
> **不预填总部模块**：`配送中心` / `生产加工` 依赖客户是否自建中央厨房/配送中心，由销售按实际情况选；预填会破坏『套餐默认决策树』（旗舰版 vs 全能版）的默认行为。

### 预填冲突与降级

- 同一句品牌名命中多个子业态（如"火锅 + 烧烤店"复合品牌）：取**最先命中**的子业态预填，其它的不叠加，避免给销售一个臃肿的默认勾选集。
- 子业态命中但餐饮类型走了『歧义 → 显式追问』路径：此时餐饮类型尚未定，**不要**先预填增值模块；等用户确认餐饮类型后再回填。
- 若客户首条消息已经显式列出了所需模块（例如"我们要 KDS 和宴秘书"），以客户表述为准，业态预填项只在客户列出的基础上补全，不覆盖客户的明确表态。
