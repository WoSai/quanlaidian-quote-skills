# 行业关键字 → 餐饮类型判定

> 当用户先描述品牌或行业、未直接给出"轻餐 / 正餐"时，skill 按下方**三级策略**判定。
> 关键词匹配对品牌名 + 用户首条消息一起做，**大小写不敏感**，中英文混排（如"国际化 Coffee"）也要命中。

## 三级策略

### 一级：高置信度 → 自动判定（不再追问，仅在摘要里展示）

命中即把 `餐饮类型` 自动设为对应值，**跳过"轻餐还是正餐？"这一问**（卡片 1 不出现此问题，兜底对话步骤 2 跳过）。在最终的『配置摘要确认』里显式标注"已根据品牌名/行业关键词 `<词>` 自动判定为 `<餐饮类型>`，如需修改请在确认环节回退"。

- **自动判定为 `轻餐`**：
  - 中文：`咖啡`、`奶茶`、`茶饮`、`烘焙`、`蛋糕`、`面包`、`甜品`、`饮品`、`快餐`、`小吃`、`卤味`、`粉面`、`小碗菜`、`早餐`
  - 英文/混排：`coffee`、`cafe`、`café`、`tea`（独立词或词缀如 `milktea` / `milk tea`）、`bakery`、`dessert`、`donut`、`bagel`、`juice`、`smoothie`
- **自动判定为 `正餐`**：
  - 中文：`火锅`、`自助餐`、`酒楼`、`中餐厅`、`宴会厅`、`海鲜酒家`、`私房菜`、`粤菜馆`、`川菜馆`
  - 英文/混排：`hotpot`、`hot pot`、`buffet`、`steakhouse`

### 二级：软推荐 → 预填 + 用户一键确认

存在地区性差异或品类边界模糊，**不自动设定**，但在卡片里把对应选项预选/标星，并在卡片 `description` 写明理由让用户确认。

- **倾向 `轻餐`**（地区差异）：`饺子`、`包子`、`馄饨`、`沙拉`、`轻食`、`寿司外带`
- **倾向 `正餐`**（地区差异）：`烤鱼`、`砂锅`、`铁板烧`

对话模板：
- "听起来是 X 行业，通常按 **<推荐类型>** 走，我先按这个推进，可以吗？"

### 三级：歧义 → 必须显式追问

命中以下词时**不要猜**，直接在卡片/对话里让用户单选「轻餐 / 正餐」，并把两种可能场景写进 `description`。

- `茶餐厅`、`日料`、`西餐`、`小笼包`、`融合菜`、`烧烤`、`bbq`、`sushi`（堂食）、`bistro`、`brunch`

## 匹配与冲突规则

- **匹配顺序**：先扫一级（高置信度），命中即返回；未命中再扫二级；最后扫三级。
- **冲突处理**：一条品牌名/行业描述同时命中一级里的 `轻餐` 词和 `正餐` 词时（罕见，例如"火锅 + 咖啡馆"复合品牌），**降级到追问**，不要自动判定。
- **一句话覆盖多个关键词**且都在同一桶：以用户主表述（出现频次更高、出现在品牌主名而非修饰语）为准。
- 用户后续否认自动判定/软推荐结果时，立即切回"轻餐 / 正餐"标准单选，并把当次判定记录到本轮上下文，避免反复推荐同一项。

## 示例

| 用户输入 | 命中关键词 | 处理 |
|---------|-----------|------|
| "国际化Coffee" | `coffee`（一级） | 自动判定 `轻餐`，跳过追问，摘要里标注 |
| "蜜雪冰城奶茶" | `奶茶`（一级） | 自动判定 `轻餐` |
| "海底捞火锅" | `火锅`（一级） | 自动判定 `正餐` |
| "XX 饺子馆" | `饺子`（二级） | 卡片预选 `轻餐`，让用户一键确认 |
| "XX 茶餐厅" | `茶餐厅`（三级） | 显式追问 |
| "XX 品牌" | 无命中 | 走标准单选 |
